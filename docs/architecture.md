# «Альфа Пульс»: решение кейса «Новостная аналитика для принятия бизнес-решений»

> Реализация: папка `alfa-pulse/` (сервис, интерфейс, агент, тесты). Запуск и сценарий проверки - в `alfa-pulse/README.md`.

Сервис в Альфа-Бизнесе, который каждое утро показывает руководителю крупной компании 3-7 событий, реально влияющих на его группу компаний, и для каждого объясняет: что произошло, почему это важно именно ему, что может случиться, как это оценивает Альфа-Банк и что можно сделать. Каждый вывод помечен источником: **факт**, **позиция Альфа-Банка** или **вывод AI**.

Цифры ниже получены на данных кейса.

---

## 1. Главная идея: «карта чувствительности» клиента

Новость сама по себе не персональна. Персональным ее делает **механизм передачи**: ставка влияет через долг и лизинг, курс через импорт, цены на топливо через закупки и т.д. Поэтому сервис строится на трех слоях:

1. **Профиль группы компаний → чувствительность к 8 факторам** (считается заранее, без LLM, объяснимо): ставка, курс, сырье, санкции/ВЭД, потребительский спрос, стройка/ипотека, налоги/регулирование, концентрация контрагентов. У каждой оценки есть «потому что» из данных клиента.
2. **Событие → какие факторы двигает и в какую сторону** (извлекает легкая LLM из текста новости или материала банка).
3. **Агент интерпретации** соединяет одно с другим, добавляет позицию банка из его аналитики и сам проверяет результат.

Так решение работает на любых новых новостях (критерий 5): мы не учим сценарии под конкретные события, а сопоставляем факторы.

### Почему именно так: что показали данные

| Наблюдение в данных | Решение |
|---|---|
| Выручку > 15 млрд руб. имеют лишь **115** компаний из 85,5 тыс., а на уровне `GROUP_ID` таких групп **341** (34,7 тыс. компаний) | Клиент сервиса = **группа компаний**; профиль агрегируется по группе с весами по выручке |
| В больших группах сотни компаний: «есть кредит хоть у одной» дает мусор | Все признаки считаются как **доля выручки группы** (кредиты у 21% выручки, ВЭД у 53% и т.д.) |
| 1,38 млн платежей; 34 тыс. внутригрупповых; 27 тыс. «самому себе»; выбросы до 1,1 трлн | Граф контрагентов **без внутригрупповых и самоплатежей**, суммы обрезаны на 99,9-м перцентиле |
| Только 28% платежей имеют обе стороны в справочнике | Доля «вне справочника» показывается как мера уверенности, а не скрывается |
| `FTS_COUNTRY_NAME` пуст в 90%, штат по СПАРК пуст в 99,8%, дубли ID (U_428697 ×6), ОКВЭД «41.2» и «41.20» | Нормализация, флаги качества в профиле, снижение уверенности вывода при пропусках |
| Все 9 PDF аналитики банка - **сканы без текста** | Однократное распознавание Qwen3-VL → текст + таблица прогнозов банка |
| «Commodities performance» из кейса нет, зато есть обзор стали **от апреля 2021** | Каждый документ банка имеет дату; старые помечаются «устарело» и не используются как текущая позиция банка |

Пример: две крупнейшие группы получили противоположные профили (`prototype/out/group_profiles.json`):

| Группа | Сектор | Ставка | Курс | Санкции/ВЭД | Стройка | Пояснение |
|---|---|---|---|---|---|---|
| group_134402 (302,7 млрд) | Оптовая торговля топливом | 0,31 | **0,50** | **0,70** | 0,35 | лизинг у 63% выручки, гарантии у 40%, ВЭД у 47% (Киргизия, Казахстан, Турция), топливо 35% выручки, крупнейший покупатель = 40% поступлений |
| group_134409 (219,5 млрд) | Девелопмент | 0,23 | 0,02 | 0,04 | **0,59** | стройка и недвижимость 48% выручки, лизинг у 36%, ВЭД почти нет |

## 2. Архитектура

```
                ┌──────────── ОФЛАЙН (раз в сутки) ────────────┐
CSV кейса ──► Профилировщик групп ──► профиль + чувствительность + граф контрагентов ──┐
PDF банка ──► Qwen3-VL (OCR) ──► База «Позиция банка»: фрагменты + таблица прогнозов + дата ─┤
                └───────────────────────────────────────────────┘                     │
                ┌──────────── ПОТОК (каждые 15 мин) ────────────┐                     │
RSS/сайты ──► Парсер ──► дедупликация ──► Gemma 4: событие → JSON ──► Хранилище событий ┤
                └───────────────────────────────────────────────┘                     ▼
Пользователь ──► API ──► Ранжировщик (формула) ──► Лента ──► Агент интерпретации ◄── инструменты
                                                       │      (план → инструменты → черновик
                                                       │       → самопроверка → исправление)
                                                       ▼
                                   Карточка события + чат «спросить» + трассировка
```

### 2.1. Парсер (подзадача 2)
- Источники: RSS и страницы ЦБ РФ, Минфина, Минэкономразвития, правительства, Интерфакса, ТАСС, РБК, «Коммерсанта» + материалы Альфа-Банка из кейса. Каждый источник - отдельный адаптер с единым интерфейсом (легко добавить новый, критерий 7).
- Очистка и **дедупликация**: шинглы + MinHash, кластеризация перепечаток в одно событие (оставляем первоисточник и время).
- **Извлечение события** (Gemma 4, строгий JSON по схеме): тип события, факторы и направление (-1..1), отрасли (ОКВЭД), страны, товары, регионы, упомянутые компании, даты, **ключевые факты с цитатами** из текста. Факт без цитаты отбрасывается.
- Текст новости всегда передается модели как **данные**, не как инструкция (защита от prompt injection).

### 2.2. Профилировщик (подзадача 1) - готов в прототипе
`prototype/profiles.py`: группа → отраслевая структура по выручке, регионы, продукты банка (доля выручки), ВЭД и страны, иностранный капитал, сырьевые позиции (своя выручка + закупки у сырьевых поставщиков), структура поставщиков и покупателей по графу платежей, концентрация контрагентов, флаги качества данных. Выход - 7 оценок чувствительности, у каждой список причин.

### 2.3. Ранжирование (подзадача 3) - готово в прототипе
```
балл = Σ_факторы чувствительность_клиента × |сила_события| × уверенность
     + совпадение стран ВЭД + совпадение отрасли/контрагентов
     × свежесть (exp(-дни/14))  × вес роли пользователя
```
- **Роль** меняет веса: финдиректору и казначейству важнее ставка и курс, главному бухгалтеру - налоги и регулирование, собственнику - стратегия и отрасль.
- **Разнообразие**: в топ-5 не более двух событий одного фактора.
- **Порог**: ниже порога событие не показывается (сервис не превращается в ленту).

Результат на одних и тех же 5 событиях (`prototype/out/ranking_demo.md`):

| Клиент | 1-е место | 2-е место |
|---|---|---|
| Топливный трейдер (ВЭД 47%) | проверка платежей с Китаем/ОАЭ | рост цен на дизель |
| Девелопер | снижение выдач ипотеки | ставка 14% |
| Автодилер (Китай, ОАЭ, Индия) | проверка платежей с Китаем/ОАЭ | замедление потребления (Альфа-Банк) |
| Медицинская группа | проверка платежей (импорт из Китая, Италии) | замедление потребления |

### 2.4. Агент интерпретации (подзадача 4, требования к агентной логике)
Собственная реализация цикла без готовых агентных фреймворков. Один агент-оркестратор и вызываемые им инструменты; отдельный «критик» как вторая роль той же системы.

**Инструменты (вызовы журналируются):**
| Инструмент | Что возвращает |
|---|---|
| `get_client_profile(group_id)` | профиль, чувствительность и причины |
| `get_event(event_id)` | факты события с цитатами и источником |
| `get_counterparty_exposure(group_id, sector/country)` | доля закупок/продаж, крупнейшие контрагенты |
| `search_bank_research(query, factor, date_from)` | фрагменты аналитики банка с документом, страницей и датой (BM25 + фильтр по фактору) |
| `get_bank_forecast(indicator)` | прогноз банка из таблицы (ставка, инфляция, ВВП, курс) с источником |
| `find_related_events(event_id)` | связанные события за 30 дней (не пересказ одной новости, критерий 6) |
| `verify_claims(draft)` | проверка: у каждого утверждения есть источник, числа совпадают с источником |

**Цикл:**
1. **План**: по факторам события и чувствительности клиента агент решает, какие инструменты нужны (например, для ставки - профиль долга, прогноз банка по ставке, связанные события по кредитованию).
2. **Сбор**: вызывает инструменты, результаты пишет в общий **контекст** (JSON), следующий шаг видит предыдущие.
3. **Черновик** по схеме (раздел 3): шесть вопросов кейса.
4. **Самопроверка** (критик, другая модель): есть ли источник у каждого факта; совпадают ли числа; не выдана ли мысль модели за позицию банка; упомянуты ли минимум 2 признака клиента; нет ли противоречия с прогнозом банка; не устарел ли документ банка.
5. **Исправление**: при провале - дополнительный поиск или переписывание (не более 2 итераций). Если данных мало - честный вывод «влияние неочевидно, нужны данные о …» с вопросом пользователю.
6. **Трасса** (критерий 12): план, вызовы, промежуточные результаты, итоговые источники сохраняются по `trace_id` и доступны в интерфейсе по кнопке «На чем основан вывод».

### 2.5. Распределение моделей и экономия бюджета (500 ₽/день)
| Задача | Модель | Почему |
|---|---|---|
| OCR аналитики банка (однократно) | Qwen3-VL-30B-A3B | единственная мультимодальная |
| Извлечение события из новости | Gemma 4 26B A4B | массовая простая задача, дешевая |
| План и интерпретация | GLM-5.3-Flash | рассуждения, качество текста |
| Критик-самопроверка | Qwen3.6 35B A3B | другая модель = меньше общих ошибок |
| Поиск связей между событиями | DeepSeek-V4.1-Flash | длинный контекст, много материалов |
| Чат «уточнить» | Kimi-K2.6 | диалог по готовому контексту |

Экономия: профили и ранжирование без LLM; извлечение событий один раз на новость (не на клиента); **двухуровневая генерация**: базовая интерпретация «событие × тип чувствительности» кэшируется и переиспользуется для похожих клиентов, персональный слой короткий; полная интерпретация строится, когда пользователь открывает карточку; кэш на 24 ч. Расход токенов меряем на каждом вызове и показываем в мониторинге.

> Вопрос организаторам: в списке разрешенных нет эмбеддинг-моделей. Пока поиск по материалам - BM25 + теги факторов/ОКВЭД; если эмбеддинги разрешат, подключаются как дополнительный ранжировщик.

## 3. Формат обмена (JSON) и пример результата

Схема разделяет три вида утверждений, как требует кейс:

```json
{
  "trace_id": "tr_2026-09-15_134402_E1",
  "client": {"group_id": "group_134402_sb", "role": "финансовый директор"},
  "event": {"id": "E1", "title": "Банк России сохранил ключевую ставку 14%", "date": "2026-09-11"},
  "relevance": {"score": 0.22, "features_used": ["лизинг у 63% выручки", "гарантии у 40%", "капиталоемкие отрасли 39%"]},
  "facts":      [{"text": "...", "source": "doc_id/url", "quote": "..."}],
  "bank_view":  [{"text": "...", "doc": "ALFA-Macro_Insights-Policy_Rate_11Sep.pdf", "page": 1, "date": "2026-09-11"}],
  "ai_view":    [{"text": "...", "based_on": ["client:лизинг", "bank_view#0"], "confidence": "средняя"}],
  "impacts":    [{"type": "риск|возможность", "mechanism": "...", "horizon": "3-6 мес", "basis": ["..."]}],
  "actions":    [{"text": "...", "product": "опционально: продукт банка"}],
  "questions":  ["что уточнить у клиента или проверить"],
  "quality":    {"checks_passed": ["sources", "numbers", "labels", "personalization"], "iterations": 1}
}
```

**Пример карточки** для топливного трейдера `group_134402` и новости о ставке (из кейса):

- **Что произошло (факт, ЦБ РФ, 11.09.2026):** ставка сохранена на 14%; совет директоров обсуждал только паузу, снижение не рассматривалось.
- **Как оценивает банк (Альфа-Банк, «Ключевая ставка ЦБ РФ», 11.09.2026, с. 1):** банк изменил прогноз: ждет сохранения 14% до конца 2026 г. вместо 13,5%; ставка на конец 2027 г. - 12%; корпоративное кредитование растет быстрее прогнозов ЦБ, следующее заседание 23 октября.
- **Почему важно вам (вывод AI на данных клиента):** у компаний с 63% выручки группы есть лизинг, у 40% - банковские гарантии; 39% выручки в капиталоемких отраслях (стройка, инфраструктура, энергетика). Если ставки по лизингу плавающие, ожидавшееся снижение платежей до конца года не наступит; стоимость гарантий тоже останется высокой.
- **Последствия:** риск - дорогое финансирование оборотного капитала в топливной торговле при высокой концентрации выручки (крупнейший покупатель дает 40% поступлений: его задержка оплаты ударит по ликвидности сильнее, чем обычно); возможность - банк ждет снижения ставки до 12% к концу 2027 г., поэтому новое финансирование разумнее брать коротким или с пересмотром ставки, а не фиксировать на пике.
- **Что можно сделать:** проверить долю плавающих ставок в лизинге; ускорить оборачиваемость дебиторки крупнейшего покупателя (например, факторинг - нативное предложение банка); учесть 14% в бюджете на 2027 г. по сценарию банка.
- **На чем основан вывод:** признаки клиента (лизинг, гарантии, концентрация покупателя), документ банка, решение ЦБ; трасса `tr_...`.

## 4. Пользовательский сценарий (подзадача 5)

1. **Главный экран Альфа-Бизнеса**: постоянный виджет «Пульс бизнеса» с числом новых значимых событий и самым важным заголовком (критерий 9).
2. **Лента «Для вашей группы»**: 3-7 карточек; на каждой бейдж «почему вам» (например, «ВЭД 47% выручки: Казахстан, Киргизия») и цветовая метка влияния (риск/возможность). Переключатель роли (финдиректор / казначейство / собственник / главбух) - лента перестраивается.
3. **Карточка события**: шесть блоков (что произошло → почему вам → последствия → как оценивает банк → что сделать → на чем основано). Три цвета для **факта / позиции банка / вывода AI**. Ссылки на первоисточник и страницу документа банка.
4. **Чат «Спросить про это событие»**: «а если ставка снизится в декабре?», «покажи по компаниям группы», «какие контрагенты затронуты» - ответы только из контекста карточки и инструментов (критерий 8).
5. **Обратная связь**: «полезно / не про нас / ошибка в факте» - идет в метрики и в разметку для настройки весов.
6. **Профиль компании**: что сервис «знает» о группе и почему; клиент может поправить (например, «лизинг у нас с фиксированной ставкой»), и интерпретации пересчитываются.

## 5. Работа с неполными и зашумленными данными (ограничение 6)
- Дубли ID: оставляется строка с максимальной выручкой, факт дубля - во флаге качества.
- ОКВЭД нормализуется (41.2 → 41.20) до сопоставления с событиями.
- Пропуски ВЭД/штата: признак не придумывается; оценка чувствительности снижается, в карточке - «данных о ВЭД нет».
- Граф платежей: без внутригрупповых и самоплатежей, обрезка выбросов; доля контрагентов «вне справочника» снижает уверенность.
- Документы банка старше 6 месяцев не используются как текущая позиция банка (обзор стали 2021 г.).
- Противоречивые новости: агент показывает обе версии и помечает «не подтверждено».

## 6. Безопасность AI-компонента (ограничение 5)
- Роли и доступ: пользователь видит только свои группы; инструменты агента вызываются с правами пользователя.
- Белый список инструментов, только чтение; никаких платежей и изменений в банке от имени агента.
- Чувствительные данные (идентификаторы, суммы платежей) не уходят в промпт в сыром виде: передаются агрегаты и доли.
- Журнал всех вызовов модели и инструментов (кто, когда, что, сколько токенов).
- Защита от инструкций внутри новостей: текст источника передается как данные, ответ валидируется по JSON-схеме.

## 7. Метрики качества и мониторинг (критерий 10)
| Слой | Метрика | Как считаем |
|---|---|---|
| Персонализация | Precision@5 значимости | еженедельная разметка экспертами 50 пар «клиент × событие» |
| Персонализация | доля «не про нас» | кнопка обратной связи |
| Факты | доля утверждений с источником; ошибки в числах | автоматический `verify_claims` + выборочная ручная проверка |
| Интерпретация | глубина: число связанных факторов, признаков клиента | автоматически из JSON |
| Позиция банка | доля карточек с позицией банка; ошибки атрибуции | автоматически + аналитики банка |
| Продукт | открытия карточек, время чтения, вопросы в чате, «полезно» | события интерфейса |
| Эксплуатация | задержка, стоимость в токенах на карточку, сбои источников | журнал |

Процесс: дашборд метрик → еженедельный разбор худших 20 карточек → правка весов ранжирования и промптов → A/B на части клиентов.

## 8. Масштабирование и сопровождение (критерий 7)
- Новая отрасль = строка в справочнике ОКВЭД → факторы; новый источник = адаптер парсера; новый тип клиента = другой порог агрегации (средний бизнес - на уровне компании).
- Профили пересчитываются ночным заданием; события - потоково; все компоненты в отдельных контейнерах.
- Версионирование промптов и весов, регрессионный набор «эталонных карточек».

## 9. Стек и репозиторий (реализовано в `alfa-pulse/`)
- Python 3.12, FastAPI, SQLite (FTS5/BM25 для аналитики банка), интерфейс - HTML/JS без сборки (макет Альфа-Бизнес); в рабочем контуре SQLite заменяется на PostgreSQL.
- `docker compose up` поднимает сервис; без ключа LLM работает режим rules с тем же агентным циклом.
- `requirements.lock`, `README.md`, `THIRD_PARTY_NOTICES.md`, `docs/openapi.json`, синтетические данные, 6 тестовых пользователей, 17 автотестов (включая LLM-режим на имитации шлюза), метрики `python -m app.cli eval`.
